# CI routing, sharding and duplicate-run removal — 16 October 2026

Purpose: review of all 461 workflow runs across the 23 pull requests since 7 October showed that the `ci:checkpoint` label gate (11 October) moved end-to-end failures from PRs to `main` rather than removing them (14 of 23 main runs and 11 of 17 manual runs red, 10 to 18 minutes each), that the label was never used, that two racy specs caused eight consecutive red main runs after the R062 spec realignment, and that the database workflow ran twice per commit on Windows with an uncached toolchain. Owner instruction: implement items 1 to 4 of that review on this branch.

Changed scope:
- `.github/workflows/ci.yml`: `changes` job classifies PR files through the GitHub API; `check` (typecheck, unit, both builds, audit), `terraform` and `e2e` run only when their inputs changed; `e2e` is a three-shard matrix that builds `dist-live-dev`, keeps `test-results/` and `playwright-report/` as artifacts and has a 25 minute timeout; `Development checks result` is the single always-posted status for branch protection; PR runs cancel superseded runs. The `labeled` trigger and `paths-ignore` are gone; documentation-only PRs now post a passing result instead of no run.
- `playwright.config.ts`: in CI one retry with `trace: on-first-retry` and an HTML report; unchanged locally.
- `tests/e2e/phase5-final-ui-independent.spec.ts` (P6 T9 partner draft retry): the post counter is monotonic while the app retries, so the exact `toBe(2)` poll missed its window on slow runners ("Expected 2, Received 5/6" in five runs). It now waits for at least two posts and asserts every retry carries the identical durable command.
- `tests/e2e/payment-command.spec.ts` (G06 bilingual review): waits for the allocation region to remount after Edit before switching language and gives the Thai region a 10 second window (three runs failed with "element(s) not found" at 5 seconds).
- `.github/workflows/database.yml` and `scripts/database/Test-CI.ps1`: push-only trigger with per-branch concurrency; `guards` job on Linux (immutability check, transferred-bytes check, runner guards); `rebuild` matrix over the new `-Group migrations|receiving|phase5|phase8` parameter; toolchain cached under `runner.temp` keyed on `database/toolchain.json`. Without `-Group` the script runs every stage as before.

Not changed: no product code, migration, deployment or validator weakening. Branch protection on `main` is not configured (GitHub reports the branch unprotected); requiring `Development checks result` is a repository setting for the owner to apply after this workflow is on `main`, because applying it earlier would block the open PRs whose heads carry the old check name.

Checks: YAML parsed; PowerShell parser accepted `Test-CI.ps1`; `playwright test --list` resolves all three shards (153/149/… of 451 tests); `git diff --check` clean. The instrumented static specs cannot sign in inside the cloud sandbox (every static spec fails identically before test logic), so the spec fixes are verified on GitHub Actions: manual dispatch run 38849371182 of `Development checks` on this branch passed every stage in 5 min 53 s (shards 150, 147 and 142 passed, none flaky), and `Database migrations` run 38849570392 passed guards and all four groups in 4 min 7 s, against a 9 to 16 minute single job before.
