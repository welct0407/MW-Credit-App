# Change notes — R112 Pay Forward Release 3, agent pay-forward options and chat purpose card, 2026-11-02

## Purpose
A slip or chat payment above what is due today either needs hand-booking or posts without the Partner choosing what the remainder does. R112 makes the receipt agent ask, then post, and makes the chat ask the same purpose question on its confirm card. Design record: the owner-approved [plan artifact](https://claude.ai/artifact/6iCRmdeKsroNkf6NxKrZBj) (Pay Forward Design, revision 6, sections 3.3, 4.0, 6 and 7, decision D7). The agent half has its own note: [integration-agent change note](../integration-agent/Change%20Logs/CHANGE_NOTES_R112_PAY_FORWARD_OPTIONS_2026-11-02.md).

## Changes
Scope: Release 3 (the plan's last release), on top of R110 (`pwa_pay_forward_plan_v1`, command v10) and R111 (V122 to V124).

Owner authority (2 November 2026): "Merge and promote to prod. Then start release 3, test it and promote to prod too". It authorizes building R112, the pull request, DEV deployment and test, and the merge and PROD promotion of the tested scope. It does not override `integration-agent/AGENTS.md`: no Instagram browser automation, no group send, default deny for any capability not already enabled.

Owner decision D7 (plan revision 6): agent slips with money beyond what is due have no default; the agent replies with numbered options and posts only the path the reply names.

Decisions recorded in the build:
- The agent loop ships with `pay_forward_options_enabled` off, because there is no DEV agent to test it. Activation is a separate owner step after PROD has V125 (see the integration-agent note).
- The agent uses the existing channel: a 1:1 Instagram DM through the official Graph API to the AI Reviewer, with the reply read by the existing signed webhook and conversation poll. No new sending, webhook or timer capability. An email-only Partner stays held (email is informational only), so nothing posts for them.
- A numbered reply (`1`, `2`, `2 <n>`, `3 <amount>`) records the chosen purpose; an unclear reply re-sends the options once per reply; no reply, no posting. The plan hash (`planSha256`) is re-checked at execution, and a changed plan stops with a notice.
- One request id per slip: a later different purpose conflicts and is never reposted.
- The chat purpose is fixed at the Confirm claim, which keeps the V118 single-claim guard: the card stores `purposeOptions` (pay forward preview, principal per loan, split), none preselected and Confirm disabled until chosen; the confirm body carries the purpose and the v10 command is built once at the claim (`store.setProposalCommand`). The chat now builds v10 for a remainder; versions 8 and 9 remain for amounts at or below what is due.
- Technical access change: V125 grants EXECUTE on `pwa_pay_forward_plan_v1` and `forecast_schedule_v1` to `mw_integration_agent` (the agent's read-only reporting role), so the agent can show the server's plan. PUBLIC and every other role stay excluded, and the migration checks the ACL.
- The agent receipt command accepts schemaVersion 9 only for a reviewed slip dated the business day; the payload limit is 65536 bytes for v9 only (16384 otherwise).
