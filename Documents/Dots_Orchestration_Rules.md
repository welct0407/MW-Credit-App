# Orchestration rules

Owner revision: **14 October 2026**. These rules apply to the current coordinator, whether Dots or Codex. They simplify execution for the two-user PWA; they do not install automations or change saved app permissions.

## 1. Read only relevant instructions

Start with applicable AGENTS, the task/continuation note and affected source. Use the [ownership table](Development_Workflow.md#repository-and-instruction-ownership) only for routing work to another component. Read historical records only when they answer a concrete dependency/recovery question. Current owner instructions supersede dated plans.

## 2. Finish authorized work

Reuse decisions and scoped approvals. Make routine reversible implementation choices and continue through relevant checks, records and publication. Ask only for a material missing decision/authority; prepare the concrete result first. If a skill/platform/automatic review blocks an action, name the action and exact stated restriction, and continue independent work.

No extra review round at every phase, save or handoff. Follow the [PWA delivery policy](PWA_Orchestration.md) rather than inventing gates. Stop when asked and stop/cancel affected workers; report any in-flight action that cannot be interrupted.

## 3. Use one executor by default

The six roles are available, not compulsory. Activate only an authorized, useful independent role and reuse existing agents. Read [Model Work Mapping](Model_Work_Mapping.md) when choosing a model/handoff. Follow the owner's current personal-execution request without delegating.

Named outside-agent contact requires explicit owner authorization; model preferences grant none. Preserve platform boundaries and unrelated chats/settings. Keep handoffs short and coordinate shared files/live services. Review worker evidence without duplicating passed checks.

## 4. Communicate useful progress

For longer work provide concise progress at least every three minutes, or more frequently when the platform requires. State what changed, what remains and actual blockers. Use bounded waits; do not create a schedule or external message to supply updates. Stop updates when work stops.

## 5. Keep records and publication small

Use one owning record for each fact. A routine change needs its concise change log, affected checks and intended Git publication; production uses the existing compact release record and runner manifest. Update current references only when facts change. No broad folder audit, duplicated hash lists or blanket dictionary rebuild for documentation.

Preserve unrelated work and private credentials/data. Follow actual repository/platform publication authority. Old proposed Custom-rule wording is not proof of a saved setting or permission to push/merge/deploy.

## 6. Respond to Grafana alerts

Retain the owner's existing 3 October scope: diagnose ecosystem alerts through the configured route and owning [alert runbook](Grafana_Alert_Troubleshooting_Runbook.md). Do not create another monitor. Verify service/environment/current condition from fresh bounded evidence and correlate repeated alerts.

Within existing authority and mandatory platform controls, an affected already-enabled worker may be restarted or demonstrably failed/unprocessed work retried only through its documented duplicate-safe recovery path. Preserve package/configuration, switches, cutoffs, review/audit and journal state. Never replay uncertain payments/sends, enable a paused service, restart a shared database/VM, clear queues or start a second worker on this authority.

The alert permission does not authorize code/configuration/schema/access/schedule/alert-rule changes. If diagnosis or safe recovery is uncertain, continue read-only analysis and report impact, evidence and the concrete proposed action to the owner. Verify actual health/progress after a repair. No new external recipient or outside-agent contact is authorized.

Saved Custom-rule proposals and prior routing discussions remain in Git tag R057 for reference. Updating these repository instructions does not change the application's permission settings.
