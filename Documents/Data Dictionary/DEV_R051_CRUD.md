# R051 DEV CRUD delta

Current DEV: OLTP1.000194 / OLAP1.000056 / PostgreSQL V72, 6 October 2026. Both editors are saved and clear; current GUI acceptance, SQL regression and exact synthetic cleanup are complete. R051 is Open; no production definition is changed. [Completion](../../outputs/r051-receipt-corrections/vm01-completion-20261006.md).

Payments are editable source records. Financial changes atomically reconcile allocations, repayments, account cash, parent balances and payment-owned closure/referral; metadata changes do not repost. The hidden Delete Requested flag and detail-only Delete receipt action avoid AppSheet's historical child-first native-delete failure. Generated child amounts remain source-managed; eligible whole-interest allocations may change charge within the same loan. Unrelated receipts remain intact.

Unpaid loans and unreceived charges permit source deletion. Paid/dependent/defaulted records display relevant bilingual reasons; backend guards remain authoritative for stale/concurrent writers. Principal cannot undercut received/booked principal. Entering daily requires the frozen original rate and, when automatic, valid schedule fields. Current daily interest recalculates; later booked charges remain separate obligations. Undo Default restores recorded components and clears all five client closure fields together.

Manual expense correction updates its single system cash movement. Deleting a reimbursed expense removes that expense's owned movement but retains the independent Lisa-to-Tommy transfer, clears its optional link and appends the original source ID to Notes. Any actual cash return is separate. Optional legacy and SQLLab assessments similarly clear only their borrower reference and retain input/snapshot history; they do not block an otherwise eligible borrower deletion.

R005 included-source edits write only the signed difference from their captured baseline, retaining membership and avoiding historical full reposts. R008 previously unassigned source cash is removed from the appropriate account opening once when assigned or deleted. Recorded account/holder attribution takes precedence; otherwise use the owner's Lisa rule and her unique active default account. Preserve original cutover values/timestamps and append opening-adjustment history to Notes. No-op edits do not duplicate accounting.

OLAP retains manual transfer, contribution and settlement ownership. Settlement Complete/Reverse/Cancel remain supported; Cancel retains history and removes owned cash. Withdrawal Net Contribution explicitly uses `0 - [Amount]`. OLAP receipt/expense mirrors stay read-only and open the exact source in canonical DEV OLTP. No restrictive dependency views were added.
