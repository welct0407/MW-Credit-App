## Claude Code only

These additions apply to Claude Code; `AGENTS.md` above is shared with Codex and stays the source of project rules.

- In a Claude Code cloud session this repository (`welct0407/MW-Credit-App`) is the only one needed; do not attach or clone sibling repositories. Tools come from [project/scripts/cloud-session-setup.sh](project/scripts/cloud-session-setup.sh); the SessionStart hook [`.claude/hooks/session-start.sh`](.claude/hooks/session-start.sh) runs `npm ci`, sets `PYTHONPATH` and `NO_PROXY` for the app origins, and prepares `/tmp/mw-labs` (`$MW_LAB_DIR`) for disposable PostgreSQL clusters as `postgres`.
- Cloud-session limits, so nobody retries them: the session proxy refuses GitHub writes other than branch pushes (no remote branch deletion, no repository settings, no deploy keys, no GraphQL); merged head branches are deleted by GitHub, and tags go through the Release tag workflow. `gh` is unauthenticated; use the `mcp__github__*` tools. Do not chain `sleep` before a command (use a background command or Monitor), and never `pkill -f` a pattern that matches your own shell. Start the named workers without worktree isolation; the one-writer rule already separates their files. Run promotion and database sessions in Accept edits mode: Auto mode's classifier denies sanctioned PROD reads, Secret Manager reads and Hosting applies.
- The PWA team workers are the Claude Code sub-agents defined in `.claude/agents/` (`archie`, `byte`, `chase`, `dewey`, `echo`, `forge`), each carrying its [roster](project/Documents/Rules/PWA_Orchestration.md#named-workers-started-once-per-session) role, default model and effort. Start a role once with the `Agent` tool using that definition as the agent type and the display name (for example `Archie (A — Architect)`), then continue that worker with `SendMessage` to its name for every later task in the session. Use `Agent` again for a role only to replace a worker the tool reports gone or to apply a [model/effort escalation](project/Documents/Rules/Model_Work_Mapping.md#claude-alternative) it cannot adopt; pass the escalated model and effort as overrides on that call, since the definition holds only the default.
- Checks and CI follow the [lean check routine](project/Documents/Rules/PWA_Orchestration.md#lean-check-routine): one push per verified batch, the pull request's `Development checks` run as the one broad run, no local wide browser suite, no polling, no manual dispatch or re-run when a run on an input-equivalent commit exists. On a pull request this session opened, [`.claude/skills/steward/SKILL.md`](.claude/skills/steward/SKILL.md) holds the same conventions for CI waits, pushes and re-runs.
- Cloud sessions signed in to GCP as `codex-cloud` reach Azure for Terraform (as `mw-credit-unattended-admin`) on demand only: prefix the command with `scripts/azure-cloud-session.sh`, which mints a one-hour token for that command and removes it afterwards; no session hooks. See [unattended-admin](infrastructure/unattended-admin/README.md). VM-01 power: `scripts/vm01-power.sh start` (or `deallocate`, `restart`).
