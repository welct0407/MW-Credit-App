## R053 maintained cutover helper

`scripts/deploy-shared-receipt-api.py` was executed after the cloud/SQL candidate and separate verified `mw_agent` PostgreSQL backup were ready. Its first install attempt stopped before package replacement because the existing virtual environment lacked `setuptools.build_meta`. Installing the pinned build prerequisite `setuptools==75.8.0` resolved that issue; the same frozen backup and unchanged candidate then passed installation and activation. Application dependencies were unchanged. The helper never copies SQLite, changes schema/generation, probes GCS, replays receipts or performs a payment POST.

Run the reviewed helper as root on `vm-mw-credit-agent`, retaining it outside the runtime checkout while checking out commits. Every phase checks metadata project, instance name and attached service account. First run `freeze --commit <exact-current-40-character-SHA>` against a clean current checkout. It records active timers, pauses six package-consuming oneshot workers' timers and lets running work finish naturally. Ingress, tunnel and SQL proxy remain running. Its private rollback directory holds hashed package and configuration copies, a phase receipt and exact timer resume list. Failure leaves timers paused for operator investigation.

Then switch the clean checkout to the published candidate and run `install --commit <exact-candidate-SHA>`. Existing build tools are reused with no dependency installation. Installed Python source is checked against the pinned checkout. Finally run `activate --commit <same-candidate-SHA> --origin <exact-prod-command-origin> --audience <same-origin> --cutoff <explicit-reviewed-timezone-bearing-cutoff> --probe-request-id <unused-version4-UUID>`. There is no implicit current-time cutoff. The probe obtains an attached-identity OIDC token as `mwagent` and requires `GET` status to return exactly unresolved before any activation write. It cannot submit a payment.

Activation preserves existing configuration and all other catalogue service flags, changing only the four `receipt_payment_api_*` fields, `code_version`, catalogue revision26 and the implemented shared receipt API capability. It rechecks package/config backup hashes and live config drift, writes/readbacks both private files while workers remain paused, then resumes only timers captured active. It does not start previously inactive timers. Private hashes/receipts remain under `/var/lib/mw-integration-agent/rollback/r053-*`; retain them with the separate PostgreSQL recovery evidence. An existing `r053-current` pointer blocks a second freeze until the operator reconciles the earlier deployment. If activation stops between file writes or timer starts, inspect the saved phase and hashes before recovery; do not blindly retry or overwrite the original backup.

Rollback is operator-controlled: pause the same timers, restore verified backed-up package/config/catalogue, then resume the captured active timers. Preserve all journal identities, API UNKNOWN status reconciliation and legacy credentials; never restore or reset financial journals as a code rollback. The helper intentionally does not automate rollback or PostgreSQL restoration.
