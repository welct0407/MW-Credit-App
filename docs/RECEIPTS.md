## Processing

1. Signed Instagram messages are durably captured before HTTP acknowledgement. Image attachment URLs are retained in the private ingress database. Text, audio, video, shares and other non-image content receive no business action or reply.
2. `receipt-cycle` processes only events with both event time and capture time at/after the immutable activation cutoff. A SQLite cursor handles bounded batches, and a process lock allows one worker. Delayed retries from before activation are excluded.
3. Fetch the sender's current Instagram profile by scoped ID; require the returned ID to match. Normalize the username and require exactly one Borrower master match with AI Collection Enabled=true. Disabled or ambiguous mappings receive no image extraction or email.
4. Download only approved HTTPS Meta CDN image URLs, with bounded redirects, image bytes and pixels. Codex sees the sanitized image and a fixed extraction prompt, never database credentials, borrower masters, account numbers to guess from, or delivery addresses. User configuration/rules, shell, subagents, web search, local image tools and apps are disabled. Output is schema constrained; the host independently validates extracted data. Image instructions have no authority.
5. Require a successful bank/PromptPay receipt, positive THB amount to two decimal places, readable transaction reference, and Bangkok date today or yesterday. Convert Buddhist dates during extraction. The same destination can match either Cash Accounts Account Number or Alternative Account Number; the displayed bank name does not split Lisa's combined account or Dad's bank/PromptPay mapping. Only Active accounts match. Masks require equal total length, at least four visible digits, and one unique Cash Account across all candidates. Unknown/ambiguous/truncated numbers fail closed.
6. Reject bank references already in Payments or this agent's accepted receipts. Canonical image pixels also detect exact-image reuse independent of file metadata. Journal uniqueness is global across borrowers, messages and restarts. This is basic duplicate validation, not bank authenticity verification or a guarantee against a modified fraudulent slip.
7. Atomically reserve receipt keys and a Partner email outbox. Use all current Partners with valid Email and supported Language Preference (English/ไทย), regardless of the statement IG Integration Enabled flag. Deduplicate shared delivery addresses; if their language preferences differ, include both languages in one message. No receipt image or full account number is emailed.
8. Re-read Borrower/Partner/account masters before each delivery. A revoked mapping, changed address/language membership, or inactive account holds delivery for review. Email states are PENDING, SENT, REJECTED, UNKNOWN or REVIEW. Commit UNKNOWN before contacting Microsoft Graph. Retry only definite rejection, at five-minute intervals, at most three total attempts; a timeout/crash/uncertain acceptance is never automatically replayed. Statement and receipt workers lock the shared OAuth refresh file during rotation.

The email says a payment **receipt** was received, gives Borrower, amount, Cash Account label, date and reference, and explicitly says **no payment record has been created**. English example: “Received a payment receipt from Test Borrower for 1,234.50 baht into TTB test.” No AppSheet mutation or durable PostgreSQL DML exists in this path. Switching to posting requires a future owner instruction and a separately implemented write service.

Invalid receipts and exhausted processing retries remain in private REVIEW state, without notifying borrowers or claiming a received bank credit. Nonreceipts and disabled/unmapped borrowers are IGNORED. Operator inspection is required for REVIEW/UNKNOWN and exhausted REJECTED cases; there is no automatic exception email channel. Image blobs are removed at terminal processing; validation metadata and delivery/dedup records are retained. Ingress URLs are private, signed references and must never be exported to source control.

## Installation and activation

Use `scripts/deploy-receipt-summary.sh` on the verified VM as root. It captures the installed package, config/catalogue, and SQLite online backups with integrity checks in `/var/lib/mw-integration-agent/rollback/receipts-<UTC>`. Statement timers are paused only during package installation and resumed. The receiver is briefly stopped for its compatible SQLite column addition; Meta retries are deduplicated. The receipt timer is installed without activation.

Sign in as mwagent with `CODEX_HOME=/var/lib/mw-integration-agent/codex-runtime` using `codex login --device-auth`; do not copy old Windows credentials. This private directory is mode 0700. Run `scripts/verify-receipt-extraction.py` as mwagent for an actual model extraction against a synthetic image and alias; it sends no mail and writes no payment. Then root runs `scripts/activate-receipt-summary.py`. It verifies authentication, production masters, config/catalogue, and synthetic proof, saves prior config, sets a new UTC cutoff once, and enables `mw-receipt-summary.timer`. Never reset the cutoff or automatically replay older captures.

Inspect `systemctl status mw-receipt-summary.timer mw-receipt-summary.service` and `journalctl -u mw-receipt-summary.service --since today`. The command reports status counts only. Private journals are `/var/lib/mw-integration-agent/state/instagram-ingress.db` and `receipt-processing.db`; summaries do not print message contents, account numbers or addresses. The existing daily statement and retry timers remain owned by their current service.
