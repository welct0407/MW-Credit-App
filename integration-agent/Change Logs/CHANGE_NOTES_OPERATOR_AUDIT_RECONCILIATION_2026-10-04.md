`operator_audit.py` adds a distinct `operator_sql_reconciliation` contract. It independently verifies the original PostgreSQL text digest, original canonical plan digest, central canonical reconciliation digest, source operation/transaction/actor labels/code revision, and the ordered immutable effect fingerprint. Existing reviewer and receipt branches retain their original checks. It attributes the legacy identity as an operator label, never as verified human reviewer membership.

The owner-run reconciliation tool defaults to read-only. A private manifest pins all original hashes and effect count plus original evidence/repair authorization references; apply requires a verified backup reference. It appends current-time retrospective linkage and an explicitly labeled reconciliation event in one central transaction, with deterministic idempotency and conflict rejection. Original in-transaction recording time is preserved as payload evidence, never relabeled as exact commit time or used to backdate central records. No business DML or notification is executed.

The scoped deployment tool drains only the existing relay, verifies a private package/config rollback copy, copies only the compatibility module and outbox dispatch, runs the unit suite, updates only deployment code-version metadata and restores only the previously active timer. No dependency, schema, credential, business switch, schedule or collector change is included. If deployment fails before resume, restore the copied package and original config using the private deployment record, then restore the prior timer state; preserve all appended audit records and new business activity.
