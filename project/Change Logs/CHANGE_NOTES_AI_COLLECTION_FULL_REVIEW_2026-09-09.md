## Repairs

| Finding | Repair / practical effect |
|---|---|
| Invalid reviewer-file edits could prevent webhook ingestion/startup | Receiver configuration no longer loads reviewer roles. Processing still requires valid roles. |
| History-first ingestion could lose a direct reply's webhook link | Matching authenticated webhook metadata enriches the existing event, without duplicating it or changing its text. |
| Repeated Approve could fail after an earlier approval succeeded | Already-approved/posting/posted receipts return their existing state and continue reconciliation; no new payment reservation. Null reply metadata is handled safely. |
| Thai bank prefix changed transaction fingerprint | Bank names with/without the Thai bank prefix now share duplicate protection, including legacy prefixed keys. |
| Missing/PDF/uninspected attachment could be classified as casual chat | Uninspected financial relevance is retained for review. Multiple relevant attachments are retained together in an explicit case rather than treating only the first as a payment. |
| An unsent acknowledgment could expire or show an old balance indefinitely | Refresh from current facts only when there is no outbox reservation; posted payment stays unchanged. |
| An unsent reminder reservation could block later cycles forever | Cancel only when no outbox exists, retaining audit record; replan from fresh data. Accepted/verified sends reconcile by readback, never resend. |
| Rejecting a waiver/extension required another resolution step | Per user confirmation, rejecting FEE_WAIVER, EXTENSION, TERM_CHANGE or NEW_LOAN closes the request and resumes existing rules. Payment disputes remain separate. |
| Standalone Node lease-renewal failure did not stop work | Exit on failed/lost renewal; durable dispatches remain available for reconciliation. |
| Borrower-directory request could follow a redirect with its access-key header | Disable HTTP redirects on that credentialed read. |
| Mixed Windows clock precision could reject a just-created snapshot | Use the same datetime clock family for the snapshot age check; freshness limits remain unchanged. |
| Worker health omitted processing state and hid outer-loop error type | Status exposes processing_enabled; health/log records exception class without private message contents. |

Duplicate-approval attempts also receive an explicit audit entry while remaining blocked.
