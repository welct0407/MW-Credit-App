## Delivery tooling status

Source inspected **18 October 2026**. This policy changes no product workflow or validator; implementation limits remain explicit:

| Tool | Actual constraint |
| --- | --- |
| App `ci.yml` | Since 16 October 2026 a `changes` job routes each run: PRs run typecheck/unit/build when app files change, Terraform validation when `infrastructure/**` changes, and the full Playwright suite (three parallel shards, one CI retry with trace, artifacts kept 7 days) when the PWA, specs, Playwright/Vite config or lockfile change. Main pushes are classified the same way from the pushed commit range (a first push or an unreadable range selects everything); manual dispatch selects every stage unless `force` is set. Since 18 October 2026 every selected stage is checked for reusable evidence: each successful stage job (check, lint, terraform, e2e shards) uploads an artifact `evidence-<workflow>-<stage>-<hash>` kept 90 days, named by a sha256 over the stage-relevant tracked files, and the `changes` job skips a stage only when it finds a trusted artifact by exact name (unexpired, same repository, same workflow file, named job succeeded in the latest attempt); the step summary cites the run, and `force` runs everything. Matching is by content, not commit history ([change note](../../Change%20Logs/CHANGE_NOTES_CI_STAGE_HASH_EVIDENCE_2026-10-18.md)). Documentation-only PRs and merges post the `Development checks result` status without running stages; that status is required on `main` since 16 October 2026. The `ci:checkpoint` label is retired. |
| `database.yml` | Push-only trigger (one run per head commit, visible on the PR); `guards` on Linux, then the four `Test-CI.ps1` groups as parallel jobs on ubuntu-latest (manual dispatch can choose windows-latest). Triggered also by `services/**`, `tests/integration/**` and `scripts/rehearsal/**`; since 18 October 2026 Markdown never triggers it and the same hash-named evidence artifacts skip a rebuild group when it passed on identical database inputs in any trusted run; a Windows dispatch always rebuilds. |
| `agent-tests.yml` | Integration agent tests (formerly the agent repository's `ci.yml`); path-filtered to `integration-agent/**` (Markdown excluded) with the same evidence artifacts (test and lab jobs) since 18 October 2026, so the merge of a tested PR into `main` does not repeat the suites. |
| `grafana-mcp-bridge.yml` | Path-filtered to `project/scripts/monitoring/...`. |
| Integration shared deployment helper | Receiver lifecycle/readiness correction is source tooling for R059; the existing R058 receiver was repaired by restart on 14 October at 18:43 Bangkok. No new runtime package was deployed for this repair. |
| Promotion runner (`scripts/promotion/deploy-business-hosting.mjs`) | The R074 contract gates CI per job: each check, e2e, terraform, guards and rebuild-group job cites a successful `ci.yml` or `database.yml` run whose head is an ancestor of the source with no stage-relevant difference (same `scripts/ci/stages.json` definition as the reuse step), or is the delivery-tool commit. A job entry may instead cite a hash-named evidence artifact (`evidence`): the runner recomputes the stage hash from the source tree and needs no ancestry check, so a pull_request or non-ancestor run is accepted; `guards` keeps the ancestor rule. Evidence from different runs is accepted, so no forced dispatch is needed ([change note](../../Change%20Logs/CHANGE_NOTES_RUNNER_PER_JOB_CI_2026-10-18.md)). R065 to R073 contracts keep their original gates. |
| Legacy foundation/business/R053 validators | Retain historical full-browser/manual-dispatch receipt requirements; they do not implement general proportional check selection. |
