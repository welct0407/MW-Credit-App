## Delivery tooling status

Source inspected **18 October 2026**. This policy changes no product workflow or validator; implementation limits remain explicit:

| Tool | Actual constraint |
| --- | --- |
| App `ci.yml` | Since 16 October 2026 a `changes` job routes each run: PRs run typecheck/unit/build when app files change, Terraform validation when `infrastructure/**` changes, and the full Playwright suite (three parallel shards, one CI retry with trace, artifacts kept 7 days) when the PWA, specs, Playwright/Vite config or lockfile change. Main pushes are classified the same way from the pushed commit range (a first push or an unreadable range selects everything); manual dispatch selects every stage unless `force` is set. Since 18 October 2026 every selected stage is checked for reusable evidence: each successful stage job (check, lint, terraform, e2e shards) uploads an artifact `evidence-<workflow>-<stage>-<hash>` kept 90 days, named by a sha256 over the stage-relevant tracked files, and the `changes` job skips a stage only when it finds a trusted artifact by exact name (unexpired, same repository, same workflow file, named job succeeded in the latest attempt); the step summary cites the run, and `force` runs everything. Matching is by content, not commit history ([change note](../../Change%20Logs/CHANGE_NOTES_CI_STAGE_HASH_EVIDENCE_2026-10-18.md)). Documentation-only PRs and merges post the `Development checks result` status without running stages; that status is required on `main` since 16 October 2026. The `ci:checkpoint` label is retired. |
