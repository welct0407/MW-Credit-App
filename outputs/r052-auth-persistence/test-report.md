## Real defect found during testing

The first implementation initialized getAuth (default IndexedDB persistence), then switched to browserLocalPersistence with setPersistence. Reload/reopen succeeded, but cross-tab logout failed: the second tab's localStorage became empty while SDK currentUser and app rows remained after the unchanged5-second assertion, even foregrounded. A/B inspected the installed SDK and confirmed the persistence swap does not rebind the listener constructed for the original store. B changed construction to public initializeAuth with the chosen LOCAL/memory persistence and popup resolver. The same cross-tab assertion then passed; no increased timeout, private SDK patch or custom token store was used.
